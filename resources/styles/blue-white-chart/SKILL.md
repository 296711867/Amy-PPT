采用清爽克制的蓝白商务图表风，整体像一份被打磨过的企业经营分析报告：理性、秩序感强、信息密度高，但不压迫。白色画布上用深蓝建立权威感，用浅蓝和灰蓝制造层级，所有视觉都服务于数据、逻辑和决策表达。

## 配色
主色是沉稳的企业深蓝 #305598，用在标题、分隔线、核心模块、数据柱和关键图形上，像一条稳定的业务主线。辅助蓝包括明亮商务蓝 #4472C4、柔和中蓝 #5B80D1、淡蓝灰 #A0B8E2、#B4C6E7、#D0DBEF，用来区分层级和模块状态。背景以干净白色 #FFFFFF 为主，局部使用极浅冷灰蓝 #F1F5F9、#F3F6FC、#F2F2F2 做信息区底色。正文常用黑灰 #000000、#262626、#404040，强调数字和标题可用深海军蓝 #00329D、#002576。整体避免花哨高饱和色，只在复杂图表中可少量引入红 #DC2626、绿 #16A34A、橙 #F59E0B 作为数据线辅助。

## 字体
标题使用思源黑体或同类粗黑体，字形方正、干净、有企业级可信度；正文和数字大量使用 Roboto，数字感清晰，适合展示百分比、金额、KPI 和趋势值。中文标题可以保持 40–53px 的大字号，正文多在 18–23px，关键数字可放大到 53–73px，让页面有强烈的数据锚点。

## 排版
版式以 16:9 宽屏画布为基础，常见结构是左上标题、下方一条深蓝横向分隔线，然后进入内容区。信息组织偏网格化和模块化：顶部 KPI 卡片、中部图表区、侧边说明区、底部结论或指标条。页面经常使用左右分栏、上下分区、四宫格卡片、时间轴、环形图和矩阵表，整体比例稳健，留白适中，强调一屏讲清楚一个业务问题。

## 图表与装饰
核心视觉语言来自数据图表和逻辑图，而不是插画。可以大量使用折线图、柱状图、饼图、环形图、气泡图、流程图、矩阵表、漏斗关系、环形整合图、年度目标闭环图、立方体组合和 KPI 数据卡。装饰元素要保持商务感：细长深蓝横线、虚线框、浅蓝半透明底板、圆环、方块、箭头、小图标式几何块。几何图形可以轻微旋转或叠放，但仍要保持精确、冷静、像咨询报告中的逻辑模型。

## 布局
优先使用大面积白底，深蓝用于建立视觉骨架。标题通常靠左，下面配一条横贯页面的蓝色细线；内容区采用严谨的对齐系统，模块之间保持明确边界。数据页可以把左侧设置为深蓝重点区，放大百分比和核心结论，右侧放图表；逻辑页可用浅蓝虚线框承载模块，中央用圆环、闭环或立体方块表现关系。不要让页面像海报一样情绪化，而要像一份董事会汇报材料，清楚、稳、可信。

## 动画
动画应当克制而专业。标题和分隔线可使用 0.4s–0.6s 的淡入或从左轻滑入；图表适合按数据系列逐步出现，柱状图从底部增长，折线图沿路径绘制，环形图顺时针展开。模块卡片可用轻微 fade-up，避免弹跳、夸张缩放或炫光效果。

## 适合场景
经营分析汇报、营销运营复盘、销售数据看板、企业战略规划、咨询报告、财务看板、项目阶段目标和企业内部汇报。它尤其适合需要大量图表、数据、流程和逻辑模型的 PPT，让信息看起来专业、可信、可执行。

## 不要
- 不要使用大面积艳丽渐变或霓虹色
- 不要使用手绘、水彩、卡通插画等松散元素
- 不要让字体过于圆润可爱或装饰化
- 不要堆叠过多阴影和复杂纹理
- 不要破坏网格对齐，所有模块都应显得精确、理性、有秩序

## PPT 演示执行契约（v3）

以下规则是本风格在当前 PPT harness 中的最终执行约束；上文负责视觉 DNA，本节负责把它落成真正的演示文稿。若上文示例与本节冲突，以本节及全局 Layout Skill 的结构安全规则为准。

### 与 Layout Skill 的边界

- 本风格只决定颜色角色、字体气质、图像处理、图表观感、形状和装饰语言；页面角色、阅读路径、信息分组、画布安全区、碰撞与高度预算由 Layout Skill 决定。
- 这是固定比例 PPT 画布，不是响应式网页。先确定“观众 3 秒后应记住的一句话”，再选封面、数据、对比、过程、时间线、概念、总结或图片主导等页面角色。
- 每页只设一个主结论和一个主视觉焦点，通常保留 2–4 组支撑信息。内容过多时先合并、删减或换构图，不缩小字号、不越过安全区。
- 全套保持统一的颜色角色、字体组合、图像色温和装饰母题，但相邻页面应变化轮廓，不能连续复制同一种卡片网格。

### 蓝白商务图表的推荐构图

- 让图表或经营结论占据主区，辅助信息压缩为一条证据带，避免 KPI 卡片铺满整页。
- 优先执行摘要、主图表 + 结论、左右对比、关键数字 + 证据链、清晰流程；一页只保留一个主结论，主体区必须明显大于辅助信息。
- 封面保持简洁；内容页让标题、主视觉/主图表和结论形成明确先后。留白围绕焦点组织，既不能拥挤，也不能出现内容只堆在上半页的意外空洞。

### 字体与信息层级

- 使用 Layout Profile 或 design contract 给出的实际字体和字号；风格只约束字形气质。无覆盖时遵守画布自适应字号下限，标题、二级标题、正文、辅助文字四级必须一眼可辨。
- 页面标题优先写成结论句，并保持单行；二级标题命名一个步骤、证据或观点，正文写短句而不是网页说明文。内容放不下时先改文案或布局，不压缩到投影不可读。
- 多行正文和模块默认左对齐；居中只用于封面、金句、单数字或极短标签。同组标题—正文间距、行距和对齐线保持一致。

### 视觉素材、图表与模块

- 图片使用真实业务场景、产品实拍或信息图，裁切干净；图表使用同一主色的明度层级，仅给关键系列使用强调色，坐标、单位、图例必须清楚。
- 模块依靠网格、细分隔线和留白建立秩序；默认不加图标底座与装饰填充，避免把商务汇报做成后台仪表盘。
- 图片、图标、图表和装饰必须支持当前结论。图标使用统一风格的 SVG/矢量图，不用 emoji、字符图标或无意义贴纸；需要替换的图片位应使用明确比例、用途和裁切建议的语义占位。
- 卡片不是默认布局。只有并列、对比、步骤或分类确实需要边界时才使用容器；同组容器的圆角、边框、阴影、图标底座和强调方式必须完全一致，且禁止卡片内再嵌套卡片。

### 反 Web UI 硬约束

- 禁止导航栏、侧边栏、标签页、按钮、搜索框、表单、状态栏、浏览器/手机窗口壳和“功能入口”式布局，除非内容本身是在展示对应产品界面。
- 禁止默认使用 dashboard、bento、四宫格/六宫格卡片墙、胶囊标签云、悬浮玻璃面板或顶部 hero + 下方功能卡片的网页套路。
- 禁止把每条提纲机械转换成一个可见模块。先围绕主结论编辑证据，再选择主图、主图表、对照、时间线、过程、引语或数字等 PPT 表达。
- 装饰不能穿过文字、抢占安全区或填补无意义空白；动画跟随阅读顺序，控制在淡入、轻移、擦除或图表生长等演示动作内，不模拟网页交互。

### 输出前自检

1. 关闭颜色与装饰后，这页是否仍能在 3 秒内读出主结论和阅读顺序？
2. 页面是否像一张演示文稿，而不是网站首页、后台面板、组件库或信息流？
3. 是否只有一个主焦点，支撑信息数量受控，并且所有正文都在安全区内、无碰撞、无截断？
4. 本页是否真正体现“蓝白商务图表”的独特色彩、字体、图像或形状语言，而非只换背景颜色？
5. 与相邻页相比，是否保持同一视觉系统但使用了不同且适合内容的页面轮廓？
